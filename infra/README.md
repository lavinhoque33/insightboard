# InsightBoard infrastructure (synth only)

Status: **M6, synth only.** This package describes the AWS experiment that a later, separately approved
milestone (M7) may deploy. Nothing here deploys, bootstraps, or calls AWS. `cdk deploy`, `cdk bootstrap`, the
AWS CLI, and any AWS credentials are **forbidden until an approved M7**. The package depends only on the
`aws-cdk-lib`, `constructs`, and `cdk-nag` libraries (no `aws-cdk` CLI, no AWS SDK) and synthesises by calling
`app.synth()` from a script. See the [M6 contract](../docs/architecture/m6-aws-readiness-contract.md) and
[ADR 0004](../docs/decisions/ADR-0004-m6-aws-readiness.md).

## What the stack contains

One environment-agnostic stack, `InsightBoardExperiment` (no account, region, or context lookup in the
template), tagged `project=insightboard` and `purpose=m7-experiment`:

- **Lambda function** `InsightBoardExperiment`: `provided.al2023`, `x86_64`, handler `bootstrap`, 512 MB, 15 s,
  outside any VPC. Code is the package `insightboard-lambda.zip` (`bootstrap`, `static/`,
  `certs/rds-global-bundle.pem`). Environment: `STATIC_DIR`, `DB_MAX_CONNECTIONS=2`, `RUST_LOG`, `DATABASE_URL`
  (`sslmode=verify-full` against the bundled RDS CA), `JWT_SECRET`, and the three provider keys. Secrets reach it
  only as CloudFormation dynamic references; `REDIS_URL` is unset, so the cache is disabled.
- **Function URL**: auth type `NONE`, buffered, no CORS (one origin serves the app and `/api`).
- **Log group** `/aws/lambda/InsightBoardExperiment`: 14-day retention, deleted with the stack.
- **RDS PostgreSQL 16**: `db.t4g.micro`, 20 GB gp3, single-AZ, encrypted, publicly accessible with
  `rds.force_ssl=1`, backups kept 1 day and deleted with the instance, no deletion protection, no final snapshot.
- **Minimal VPC for RDS only**: two public subnets, an internet gateway, no NAT gateway, no endpoints; a
  security group allowing TCP 5432 from any IPv4 address (the function has no fixed address; decision 8).
- **Two Secrets Manager secrets**, generated by CloudFormation and deleted with the stack: the database
  credentials (alphanumeric password, safe inside the URL) and the app secret (generated `JWT_SECRET`, empty
  provider keys that the owner fills in M7; blank means unset in the backend).

The template contains no NAT gateway, Elastic IP, custom resource, or helper Lambda, and no secret value.

## Commands

Run from `infra/` with the repository's Node (20.19.0):

```sh
npm ci              # install the pinned libraries from package-lock.json
npm run check       # type-check, node:test assertion tests, guarded synth
npm run cfn-lint    # lint cdk.out/*.template.json (run after a synth)
```

`npm run build`, `npm test`, and `npm run synth` run the steps individually. From the repository root,
`make lambda-build` builds the package (Docker only), `make infra-check` runs `npm ci`, `npm run check`, and
`npm run cfn-lint`, and `make infra-synth` runs the synth alone; both infra targets stop if the package is missing.

The synth reads the Lambda package from `LAMBDA_ASSET`, a path relative to `infra/` or absolute, defaulting to
`../backend/target/lambda/insightboard-lambda.zip` (built by `make lambda-build`). A missing file is an error.
The template goes to `cdk.out/InsightBoardExperiment.template.json` (gitignored); the synth prints its path and
SHA-256. The asset hash, and therefore the template checksum, follows the package contents.

`npm run cfn-lint` runs a pinned `cfn-lint` inside a throwaway `python:3.12-slim` container with the templates
mounted read-only; nothing is installed on the host. It fails on errors and warnings.

## Guardrails

- The synth refuses to run, with a non-zero exit, if any of `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`,
  `AWS_SESSION_TOKEN`, `AWS_PROFILE`, or `AWS_WEB_IDENTITY_TOKEN_FILE` is set, even to an empty value.
- It works offline: inside a container with `--network none` and an empty home directory.
- It fails on any unacknowledged finding of any severity from the cdk-nag `AwsSolutions` pack or CDK's
  built-in offline CloudFormation validation, and on any error or warning annotation.
- Every accepted finding is acknowledged on the single resource it concerns, by rule ID, with a reason that
  names the contract decision. The one exception is `CloudFormation-Validate::W3010`, which `aws-cdk-lib`
  acknowledges itself when a stack reads `availabilityZones` (the template uses `Fn::GetAZs`, not literal zones).
  The reasons are written into the template (`Metadata.cdk_nag.rules_to_suppress`) and printed by the synth. Two
  cfn-lint warnings are ignored on their resource (`Metadata.cfn-lint`), with the reasons in `src/stack.ts`.
- Tests and the synth never contact AWS. The template's bootstrap-version rule and asset bucket name are
  deploy-time references that M7 must settle before any deploy.
