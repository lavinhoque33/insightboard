## Report summary: 2026-10-10-08/M6CodeSeams

- Report source / role: `research-medium` M6CodeSeams, read-only.
- Reported state: submitted.
- Findings:
  - `app::router(AppState)` builds without a socket. The crate is binary-only, and its tests live in
    `backend/src/tests/`.
  - The couplings to a long-lived process are: `ConnectInfo` in `limit_auth` (`ratelimit.rs:63-77`, with a
    shared-bucket fallback), the `spawn_cleanup` task, migrations at startup, `dotenvy`, and the pool's
    `max_connections` of 10.
  - Auth is HS256 with `sub` = `users.id`, and there is no provisioning path. A Cognito token needs RS256/JWKS,
    first-sight provisioning, an email-collision policy, and a frontend flow.
  - sqlx 0.8.6 and redis 0.27.6 have no TLS features (D21 row quoted). reqwest 0.12.28 runs on native TLS.
  - The frontend calls a relative `/api`.
  - CI has a natural place for a `--features lambda` step and an infra job.
- Checks / evidence: file reads only.

## Report summary: 2026-10-10-08/M6Ecosystem

- Report source / role: `research-medium` M6Ecosystem, read-only web research (public pages only, retrieved
  2026-10-10). No AWS account or CLI interaction.
- Reported state: submitted.
- Findings:
  - `lambda_http` 1.3.1 has MSRV 1.84 and pulls no TLS crate. Under it, the source address comes from
    `RequestContext::ApiGatewayV2.http.source_ip`.
  - cargo-lambda needs Zig by default; only `deploy` needs credentials.
  - CDK v2 synthesises offline if it avoids lookups and uses an environment-agnostic or dummy environment.
  - `sam validate` needs credentials.
  - OpenTofu `plan` without credentials is unreliable [INFERENCE].
  - Cognito: 10,000 MAU free on Lite and Essentials. `jsonwebtoken` 9.3.1 verifies RS256 against a JWKS.
  - Cost traps: a NAT gateway (about $33 a month), a public IPv4 address ($3.65 a month), ElastiCache minimums, and
    RDS snapshots left behind on delete.
  - Guardrails: alerting budgets are free.
- Uncertainties it flagged: the axum 0.7 compile, CDK synth's network behaviour, unfetched prices, and Aurora DSQL
  compatibility.

## Main-thread review: 2026-10-10-08/M6 contract

- Decision: both reports **accepted** as inputs. Contract and ADR 0004 drafted as **proposed**.
- Checks executed by the main thread, all **observed**:
  - A throwaway crate in `/tmp`, since removed, passed `cargo check` with `axum` 0.7.9 and `lambda_http` 1.3.1
    (`apigw_http`). It included a `map_request` layer that inserts `ConnectInfo` from the source address.
    `lambda_runtime` resolved to 1.4.0 and `tower` to 0.5.3, and no rustls, openssl, or native-tls crate appeared in
    its tree. This resolves the research's compile uncertainty.
  - npm registry: `aws-cdk-lib` 2.273.0 declares `node >=20.0.0`, and `cdk-nag` 3.0.2 declares `>=18.12.0`.
  - Docker Hub: `amazon/aws-lambda-provided:al2023` exists (amd64, last updated 2025-01-14).
  - This workstation has no `~/.aws` and no AWS credential variables. No AWS, CDK, SAM, OpenTofu, Terraform,
    cargo-lambda, Zig, or cfn-lint is installed.
  - `/readyz` requires Redis (`backend/src/handlers/health.rs:20-29`), so the no-Redis shape needs the explicit
    cache-disabled mode in contract section 4.
- Main-thread design choices beyond the reports, each recorded with alternatives in the contract:
  - one Lambda function behind a Function URL that serves the app and the API from one origin (reuses M5 decision 1;
    the source address is real);
  - a static x86_64 musl build in the pinned Rust container, avoiding Zig and cargo-lambda;
  - rustls everywhere, which removes OpenSSL;
  - no CDK CLI installed, so there is no deploy path;
  - the synth script refuses to run when AWS credential variables are set.
